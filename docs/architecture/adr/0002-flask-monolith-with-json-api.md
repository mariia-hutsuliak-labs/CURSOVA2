# ADR-0002: Монолітний Flask-застосунок із серверним рендерингом і вбудованим JSON API

- **Номер:** 0002
- **Статус:** Accepted (прийнято)
- **Дата фіксації:** 2026-11-14 (ретроспективний запис рішення, прийнятого на старті проєкту у вересні 2026)
- **Власник:** Mariia Hutsuliak

## Контекст

Курсовий проєкт розробляє одна людина за обмежений час. Потрібні і сторінки для співробітників книгарні (CRUD над товарами, продажами, поставками), і програмний доступ до аналітики та privacy-функцій. Команди DevOps немає, інфраструктура мінімальна (ISD §1).

## Розглянуті альтернативи

| Альтернатива | Плюси | Мінуси |
|---|---|---|
| Окремий frontend (React/Vue) + окремий REST/GraphQL backend | чіткий поділ, зручно масштабувати команди | два проєкти, два конвеєри, CORS і автентифікація між ними, надмірно для одного розробника |
| Мікросервіси (облік, аналітика, privacy) | незалежне розгортання | складна інфраструктура, розподілені транзакції для продажу й залишків |
| Django | вбудовані адмінка, ORM, міграції | більше «магії», інший стек, ніж у вихідній кодовій базі |
| **Flask-моноліт: Jinja2-сторінки + JSON-маршрути `/api/*` в одному застосунку** | мінімум рухомих частин, одна сесійна автентифікація (Flask-Login), швидка розробка | всі маршрути в одному `app.py` (великий файл, високий churn), складніше масштабувати окремі частини |

## Рішення

Реалізувати систему як один Flask-застосунок: HTML-сторінки рендеряться на сервері (Jinja2), аналітика й privacy віддаються JSON-маршрутами `/api/*`, ролі контролюються декоратором `requires_role`. Окремі зони відповідальності (аналітичний шар `analytics/`, Value Objects продажу, privacy, resilience) винесені в модулі поза `app.py`.

## Наслідки

- (+) Одне розгортання, одна сесія, просте локальне середовище.
- (+) Модульні межі (`analytics/`, `privacy/*`, `sale_values.py`) дозволяють пізніше виокремити сервіси.
- (−) `app.py` залишається hotspot (найбільше комітів і складності, див. звіти ЛР7), його рефакторинг триває.
- (−) Масштабування лише цілим застосунком.
- (−) Dev-сервер Flask (`debug=True`) непридатний для production; потрібен WSGI-сервер (ISD §2).
