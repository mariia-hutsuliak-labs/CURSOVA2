# Release Checklist (go/no-go) для RFC-001

Чек-лист готовності релізу. Рішення **go** (розгортати) ухвалюється лише тоді, коли виконано всі критерії; будь-який невиконаний критерій означає **no-go**, розгортання не починається, а заявка повертається в стан Assessment ([регламент CCB](ccb-charter.md)). Заповнюється безпосередньо перед вікном 2026-11-24, 20:00-22:00.

Позначка: `[ ]` не виконано, `[x]` виконано (з датою і доказом).

## 2. Ланцюг простежуваності релізу

Ланцюг доводить, що кожна зміна в продукті має причину і докази. Порядок: вимога → RFC → коміти → тести → CHANGELOG → тег Git → артефакт збірки.

| Ланка | Артефакт | Статус |
|---|---|---|
| Вимога | мінус ADR-0001: «схема створюється `db.create_all()` без інструмента міграцій, зміни схеми вручну»; ризик у [ISD §8.2](../architecture/isd.md) | [є] |
| RFC | [RFC-001](RFC-001.md), рішення CCB [ccb-protocol-RFC-001.md](ccb-protocol-RFC-001.md) | [є] |
| Коміти | `docs(change): add RFC-001, impact analysis and CCB protocol`; `feat(db): add alembic baseline migration`; `refactor(db): replace create_all with alembic upgrade in init_db and tests`; `docs(adr): add ADR-0005 versioned migrations`. Хеші вписуються після появи комітів | [ціль] |
| Тести | `tests/test_migrations.py` і повний набір `tests/` (95 тестів плюс нові); результат прогону на `bookstore_staging` зберігається разом із чек-листом | [ціль] |
| CHANGELOG | запис у розділі `Added`/`Changed`: «Міграції схеми через Alembic (RFC-001)» | [ціль] |
| Тег Git | `v1.1.0` (змінюється схема розгортання, поведінка API не змінюється, тому minor); існуючі теги `docs-v1.0`, `docs-v2.0` стосуються лише документації | [ціль] |
| Артефакт збірки | (а) архів вихідного коду GitHub Release `v1.1.0`; (б) сайт документації, який збирає конвеєр `Docs` (артефакт `github-pages`, файл `.github/workflows/docs.yml`). Окремого бінарного артефакта проєкт не має: застосунок запускається з вихідного коду | [ціль] |

Для кожного релізу ланцюг заповнюється повністю до закриття заявки (стан Closed у трекері).
