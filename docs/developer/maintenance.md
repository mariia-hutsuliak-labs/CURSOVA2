# Регламент підтримки документації (Documentation Maintenance Regime)

## Головне правило

**Зміна коду = зміна документації.** Жодне злиття до `main` не проходить без оновлення зачеплених документів у тому самому коміті або pull request. Перевірка автоматизована: `bash scripts/doc-audit.sh` повертає код 1, якщо в коді з'явився маршрут `/api/*` чи змінна середовища, яких немає в SDD/ISD, або документ відстав від коду більш ніж на 20 комітів.

## Пороги (з аудиту ЛР10)

| Показник | Підозріло | Критично |
|---|---|---|
| Last Updated Age (дні від останнього коміту документа) | понад 90 | понад 180 |
| Code-Doc Change Ratio (коміти коду після останнього оновлення документа) | | понад 20 |
| Structure Drift / Config Drift (маршрути й змінні без опису) | | будь-яке значення понад 0 |

## Власники та цикли перегляду

Цикл залежить від критичності: експлуатаційна документація переглядається не рідше ніж раз на 90 днів, архітектурна раз на 180 днів.

## Процедура

1. Перед злиттям: `bash scripts/doc-audit.sh`. Код 0 дозволяє злиття.
2. Якщо змінилася поведінка для користувача, оновіть `README.md`. Якщо змінилися компоненти, маршрути чи модель даних, оновіть `docs/architecture/sdd.md`. Якщо змінилися змінні середовища, порядок запуску, CI/CD чи відновлення, оновіть `docs/architecture/isd.md` і `.env.example`.
3. Після перегляду змініть колонку «Дата останнього перегляду» в таблиці вище.
4. ADR не переписуються заднім числом: застаріле рішення отримує статус `Superseded by ADR-NNNN`, а нове рішення оформлюється новим номером.
5. Артефакт без споживача (Dead Documentation) отримує в паспорті `status: deprecated` та `superseded_by`, а на сторінці банер із посиланням на заміну. Сторінка лишається доступною за старою адресою і видаляється лише за наступного перегляду.

## Автоматичний аудит і знімки

Конвеєр `Docs` на кожному пуші запускає `scripts/check_review_dates.py`: він виводить сторінки з простроченим `review_date` та окремо застарілі сторінки. Паспорт без обов'язкових полів вважається дефектом і зупиняє конвеєр. Стан документації фіксується анотованими тегами `docs-vMAJOR.MINOR`.
